## 1. 概述

### 1.1. NoSQL数据模型特点

**NoSQL数据模型特点**：

1. **灵活性**：支持动态模式，无需预定义schema
2. **可扩展性**：易于水平扩展
3. **高性能**：针对特定场景优化
4. **多样性**：支持多种数据模型

### 1.2. 数据模型设计原则

**NoSQL数据模型设计原则**：

1. **查询驱动**：根据查询模式设计数据模型
2. **反规范化**：允许数据冗余以提高查询性能
3. **嵌入优先**：优先考虑嵌入而非引用
4. **分片友好**：考虑分片键设计

## 2. 数据结构设计

### 2.1. 键值数据结构

#### 2.1.1. 键值对结构

**键值对结构**：

```python
{
    "key": "user:123",
    "value": {
        "name": "Alice",
        "age": 30,
        "email": "alice@example.com"
    }
}
```

**键设计原则**：

1. **唯一性**：键必须唯一
2. **可读性**：键应该有意义
3. **命名空间**：使用命名空间避免冲突

**键命名规范**：

```python
# 用户数据
"user:123"
"user:123:profile"
"user:123:orders"

# 会话数据
"session:abc123"

# 计数器
"counter:pageviews"
```

#### 2.1.2. 值类型

**值类型**：

1. **字符串**：简单字符串值
2. **对象**：JSON对象
3. **数组**：JSON数组
4. **二进制**：二进制数据

**Redis值类型**：

```bash
# 字符串
SET user:1 "Alice"

# 哈希
HSET user:1 name "Alice" age 30

# 列表
LPUSH orders:1 "order1" "order2"

# 集合
SADD tags:1 "python" "database"

# 有序集合
ZADD leaderboard 1000 "user:1"
```

### 2.2. 文档数据结构

#### 2.2.1. 文档结构

**文档结构**：

**嵌套文档设计**：

### 2.3. 列族数据结构

#### 2.3.1. 列族结构

**列族结构**：

```python
# HBase列族结构
{
    "row_key": "user:123",
    "column_families": {

            "name": "Alice",

            "email": "alice@example.com"
        },
        "orders": {
            "order:101": "200",
            "order:102": "150"
        }
    }
}
```

#### 2.3.2. 列族设计

**列族设计原则**：

1. **访问模式**：根据访问模式设计列族
2. **列数限制**：避免列族过多
3. **版本控制**：考虑版本控制需求

**Cassandra表设计**：

```cql
-- 用户表
CREATE TABLE users (
    user_id UUID PRIMARY KEY,
    name TEXT,
    email TEXT,
    age INT
);

-- 订单表（分区键：user_id，聚类键：order_date）
CREATE TABLE orders (
    user_id UUID,
    order_date TIMESTAMP,
    order_id UUID,
    amount DECIMAL,
    PRIMARY KEY (user_id, order_date, order_id)
) WITH CLUSTERING ORDER BY (order_date DESC);
```

### 2.4. 图数据结构

#### 2.4.1. 节点结构

## 3. 索引与查询

### 3.1. 主键索引

#### 3.1.1. 主键设计

**主键设计原则**：

1. **唯一性**：保证唯一性
2. **不可变**：主键不可修改
3. **查询友好**：支持快速查询

**MongoDB主键**：

```javascript
// 自动生成ObjectId
db.users.insert({
  name: "Alice"
  // _id自动生成
})

// 自定义主键
db.users.insert({
  _id: 123,
  name: "Alice"
})
```

### 3.2. 二级索引

#### 3.2.1. 二级索引设计

**二级索引**：非主键字段的索引。

**MongoDB二级索引**：

```javascript
// 创建单字段索引
db.users.createIndex({ email: 1 })

// 创建唯一索引
db.users.createIndex({ email: 1 }, { unique: true })

// 创建稀疏索引
db.users.createIndex({ phone: 1 }, { sparse: true })
```

**Cassandra二级索引**：

```cql
-- 创建二级索引
CREATE INDEX idx_email ON users(email);

-- 使用索引查询
SELECT * FROM users WHERE email = 'alice@example.com';
```

### 3.3. 复合索引

#### 3.3.1. 复合索引设计

**复合索引**：多个字段组成的索引。

**MongoDB复合索引**：

```javascript
// 创建复合索引
db.orders.createIndex({ user_id: 1, order_date: -1 })

// 可以使用索引的查询
db.orders.find({ user_id: 123 })  // 使用索引
db.orders.find({ user_id: 123, order_date: { $gte: ISODate("2024-01-01") } })  // 使用索引

// 不能使用索引的查询
db.orders.find({ order_date: { $gte: ISODate("2024-01-01") } })  // 不使用索引
```

**索引选择原则**：

1. **最左前缀**：遵循最左前缀原则
2. **字段顺序**：考虑字段选择性和查询频率
3. **覆盖查询**：尽量覆盖常用查询

### 3.4. 图索引

#### 3.4.1. 图索引设计

**Neo4j索引**：

```cypher
// 创建节点索引
CREATE INDEX ON :User(id)
CREATE INDEX ON :User(email)

// 创建复合索引
CREATE INDEX ON :User(id, name)

// 使用索引
MATCH (u:User {id: 123})
RETURN u
```

## 4. 数据模型设计模式

### 4.1. 反规范化设计

#### 4.1.1. 反规范化原则

**反规范化**：允许数据冗余以提高查询性能。

**反规范化示例**：

```javascript
// 规范化设计（需要JOIN）
// users集合
{ _id: 1, name: "Alice" }

// orders集合
{ _id: 101, user_id: 1, amount: 200 }

// 反规范化设计（嵌入用户信息）
// orders集合
{
  _id: 101,
  user_id: 1,
  user_name: "Alice",  // 冗余字段
  amount: 200
}
```

### 4.2. 嵌入vs引用

#### 4.2.1. 嵌入策略

**嵌入适用场景**：

1. **一对一关系**：用户-配置文件
2. **一对少关系**：用户-少量订单
3. **频繁访问**：经常一起访问的数据

**嵌入示例**：

```javascript
// 嵌入订单到用户文档
{
  _id: 1,
  name: "Alice",
  orders: [
    { id: 101, amount: 200 },
    { id: 102, amount: 150 }
  ]
}
```

#### 4.2.2. 引用策略

**引用适用场景**：

1. **一对多关系**：用户-大量订单
2. **多对多关系**：用户-产品
3. **独立访问**：独立访问的数据

**引用示例**：

```javascript
// 用户文档
{
  _id: 1,
  name: "Alice",
  order_ids: [101, 102, 103, ...]  // 引用订单ID
}

// 订单文档
{
  _id: 101,
  user_id: 1,
  amount: 200
}
```

### 4.3. 分片键设计

#### 4.3.1. 分片键选择

**分片键选择原则**：

1. **均匀分布**：数据均匀分布到各分片
2. **查询模式匹配**：匹配主要查询模式
3. **避免热点**：避免单分片成为热点

**MongoDB分片键**：

```javascript
// 分片键：user_id
sh.shardCollection("mydb.orders", { user_id: 1 })

// 复合分片键：user_id + order_date
sh.shardCollection("mydb.orders", { user_id: 1, order_date: 1 })
```

## 8. 形式化定义

### 8.1. 数据模型形式化

**数据模型定义**：

设数据模型 $M = (S, I, Q)$，其中：

- $S$：数据结构（Structure）
- $I$：索引集合（Index Set）
- $Q$：查询语言（Query Language）

### 8.2. 索引形式化

**索引定义**：

设索引 $I = \{(k, loc) | k \in K, loc \in L\}$，其中：

- $K$：键集合
- $L$：位置集合
