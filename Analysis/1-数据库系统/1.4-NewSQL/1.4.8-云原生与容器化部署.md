## 1. 概述

### 1.1. 云原生定义

**云原生（Cloud Native）**是一种构建和运行应用程序的方法，充分利用云计算的优势：

1. **容器化**：使用容器打包应用
2. **微服务**：应用拆分为微服务
3. **动态编排**：使用编排系统管理容器
4. **DevOps**：持续集成和持续部署

**云原生架构**：

```mermaid
graph TB
    App[应用] --> Container[容器]
    Container --> Orchestrator[编排系统]
    Orchestrator --> Cloud[云平台]

    Cloud --> Compute[计算资源]
    Cloud --> Storage[存储资源]
    Cloud --> Network[网络资源]
```

### 1.2. 容器化优势

**容器化的优势**：

1. **环境一致性**：开发、测试、生产环境一致
2. **快速部署**：秒级启动和停止
3. **资源隔离**：进程级资源隔离
4. **易于扩展**：水平扩展简单
5. **版本管理**：镜像版本管理

**对比传统部署**：

| 特性 | 传统部署 | 容器化部署 |
|------|---------|-----------|
| **启动时间** | 分钟级 | 秒级 |
| **资源利用率** | 低 | 高 |
| **环境一致性** | 难保证 | 易保证 |
| **扩展性** | 复杂 | 简单 |
| **版本管理** | 复杂 | 简单 |

## 2. 容器化部署

### 2.1. Docker容器化

#### 2.1.1. Docker基础

**Docker架构**：

```mermaid
graph TB
    Client[Docker客户端] --> Daemon[Docker守护进程]
    Daemon --> Images[镜像仓库]

    Images --> Registry[镜像注册表]
```

#### 2.1.2. Dockerfile编写

**TiDB Dockerfile示例**：

```dockerfile
# TiDB Dockerfile
FROM ubuntu:20.04

# 安装依赖
RUN apt-get update && apt-get install -y \
    wget \
    curl \
    && rm -rf /var/lib/apt/lists/*

# 安装TiDB
RUN wget https://download.pingcap.org/tidb-latest-linux-amd64.tar.gz && \
    tar -xzf tidb-latest-linux-amd64.tar.gz && \
    mv tidb-latest-linux-amd64/bin/* /usr/local/bin/ && \
    rm -rf tidb-latest-linux-amd64*

# 创建数据目录
RUN mkdir -p /var/lib/tidb/data

# 暴露端口
EXPOSE 4000 10080

# 启动命令
CMD ["tidb-server"]
```

**多阶段构建**：

```dockerfile
# 构建阶段
FROM golang:1.19 AS builder
WORKDIR /app
COPY . .
RUN go build -o tidb-server ./cmd/tidb-server

# 运行阶段
FROM ubuntu:20.04
RUN apt-get update && apt-get install -y ca-certificates
COPY --from=builder /app/tidb-server /usr/local/bin/
CMD ["tidb-server"]
```

### 2.2. 容器镜像构建

#### 2.2.1. 镜像构建最佳实践

1. **使用多阶段构建**：减小镜像大小
2. **使用.dockerignore**：排除不需要的文件
3. **层缓存优化**：合理安排COPY顺序
4. **使用官方基础镜像**：安全可靠
5. **最小化镜像**：只包含必要组件

**.dockerignore示例**：

```dockerignore
# .dockerignore

*.md
*.log
node_modules

```

#### 2.2.2. 镜像版本管理

**版本标签策略**：

```bash

docker build -t tidb:v6.5.0 .

# 推送到仓库
docker tag tidb:latest registry.example.com/tidb:latest
```

### 2.3. 容器编排

#### 2.3.1. Docker Compose

**docker-compose.yml示例**：

```yaml
version: '3.8'

services:
  pd:
    image: pingcap/pd:latest
    ports:
      - "2379:2379"
    volumes:
      - pd-data:/data

      - --name=pd1
      - --client-urls=http://0.0.0.0:2379
      - --peer-urls=http://0.0.0.0:2380

    image: pingcap/tikv:latest

    ports:
      - "4000:4000"
      - "10080:10080"

      - pd

      - --store=tikv
```

## 3. Kubernetes部署

### 3.1. Kubernetes基础

#### 3.1.1. Kubernetes架构

**Kubernetes组件**：

```mermaid
graph TB
    Master[Master节点] --> API[API Server]
    Master --> Scheduler[Scheduler]
    Master --> Controller[Controller Manager]
    Master --> etcd[etcd]

    Node[Node节点] --> Kubelet[Kubelet]
    Node --> Proxy[Kube Proxy]
    Node --> Pod[Pod]

    API --> Kubelet
    Scheduler --> Kubelet
```

#### 3.1.2. 核心概念

**Kubernetes核心资源**：

1. **Pod**：最小部署单元
2. **Deployment**：无状态应用部署
3. **StatefulSet**：有状态应用部署
4. **Service**：服务发现和负载均衡
5. **ConfigMap**：配置管理
6. **Secret**：密钥管理
7. **PersistentVolume**：持久化存储

### 3.2. StatefulSet部署

#### 3.2.1. StatefulSet特点

**StatefulSet特性**：

1. **稳定的网络标识**：每个Pod有唯一标识
2. **有序部署**：按顺序创建和删除
3. **持久化存储**：每个Pod有独立的存储

**StatefulSet示例**：

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: tidb-cluster
spec:
  serviceName: "tidb"
  replicas: 3
  selector:
    matchLabels:
      app: tidb
  template:
    metadata:
      labels:
        app: tidb
    spec:
      containers:
      - name: tidb
        image: pingcap/tidb:latest
        ports:
        - containerPort: 4000
          name: mysql
        - containerPort: 10080
          name: status
        volumeMounts:
        - name: data
          mountPath: /var/lib/tidb
        env:
        - name: PD_ADDRESS
          value: "pd-service:2379"
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes: [ "ReadWriteOnce" ]
      resources:
        requests:
          storage: 100Gi
```

#### 3.2.2. Service配置

**Service示例**：

```yaml
apiVersion: v1
kind: Service
metadata:
  name: tidb-service
spec:
  type: LoadBalancer
  ports:
  - port: 4000
    targetPort: 4000
    protocol: TCP
    name: mysql
  selector:
    app: tidb
```

### 3.3. Operator模式

#### 3.3.1. Operator概念

**Operator**是Kubernetes的扩展，用于管理复杂的有状态应用。

**Operator架构**：

```mermaid
graph TB
    User[用户] --> CR[自定义资源]

    Controller --> K8S[Kubernetes API]
    Controller --> App[应用]

    Controller --> Reconcile[Reconcile循环]
    Reconcile --> Desired[期望状态]
    Reconcile --> Current[当前状态]
```

### 3.4. Helm Chart

#### 3.4.1. Helm基础

**Helm**是Kubernetes的包管理工具。

**Helm Chart结构**：

```text
tidb-chart/
├── Chart.yaml
├── values.yaml
├── templates/
│   ├── deployment.yaml
```

#### 3.4.2. Helm部署

**使用Helm部署**：

```bash

helm repo add pingcap https://charts.pingcap.org

# 安装TiDB
helm install tidb-cluster pingcap/tidb-cluster \
  --set pd.replicas=3 \
  --set tikv.replicas=3 \
  --set tidb.replicas=2

# 升级
helm upgrade tidb-cluster pingcap/tidb-cluster \
  --set tidb.replicas=3

# 卸载
helm uninstall tidb-cluster
```

### 8.3. 备份与恢复

#### 8.3.1. 备份策略

**CronJob备份**：

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: tidb-backup
spec:
  schedule: "0 2 * * *"  # 每天凌晨2点
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: backup
            image: pingcap/tidb-backup:latest
            command:
            - /bin/sh
            - -c
            - |
              mysqldump -h tidb-service -u root -p$MYSQL_ROOT_PASSWORD \
                --all-databases > /backup/backup-$(date +%Y%m%d).sql
            volumeMounts:
            - name: backup-volume
              mountPath: /backup
          volumes:
          - name: backup-volume
            persistentVolumeClaim:
              claimName: backup-pvc
```

## 9. 形式化定义

### 9.1. 云原生系统形式化

**云原生系统定义**：

设云原生系统为 $CN = (C, O, S, M)$，其中：

- $C$：容器集合
- $O$：编排系统
- $S$：服务集合
- $M$：监控系统

**可用性定义**：

$$Availability = 1 - (1 - p)^n$$

其中 $p$ 是单节点可用性，$n$ 是节点数。
